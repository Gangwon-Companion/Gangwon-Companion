# AI 여행 취향 프로필 통합 계획

## 목표

사용자의 검색·방문·저장 코스·리뷰 활동을 LLM이 종합해 여행 취향 프로필을 생성하고, BE가 결과를 저장·갱신한 뒤 기존 여행 추천의 보조 선호로 전달한다.

## 핵심 원칙

- LLM이 여행자 유형, 제목, 설명, 태그와 근거를 직접 분석한다.
- 코드는 최소 데이터, 허용 Enum, 출력 길이, 실제 입력 근거와 민감정보 추론 금지를 검증한다.
- LLM 분석 실패 또는 검증 실패 시 기존 결정론적 분류기를 fallback으로 사용한다.
- 사용자가 현재 추천 요청에서 명시한 조건은 저장된 프로필보다 항상 우선한다.
- 반려동물, 휠체어, 가격 등 hard constraint는 프로필로 추론하지 않는다.
- FE는 프로필을 추천 요청에 직접 주입하지 않는다. BE가 인증 사용자 기준으로 저장된 프로필을 조회해 AI 내부 요청에 추가한다.
- 프로필이 없거나 만료돼도 기존 여행 추천은 정상 동작해야 한다.

## 저장 및 갱신 정책

- `COMPLETED` 프로필 유효기간: 분석 시각부터 7일
- `INSUFFICIENT_DATA` 재분석 대기시간: 분석 시각부터 1일
- `analysis_version`이 현재 버전과 다르면 만료 처리
- AI 호출 실패 시 저장된 기존 프로필을 유지
- 만료 프로필은 추천에 사용하지 않고 사용자 요청에 따라 비동기 재분석
- 동일 사용자의 활성 분석 Job은 하나만 유지

초기 통합에서는 `analyzed_at`을 기준으로 유효기간을 계산한다. 별도 `expires_at` 컬럼과 활동 이벤트 기반 자동 재분석은 운영 데이터가 쌓인 뒤 추가한다.

## 내부 추천 계약

FE 공개 요청에는 기존 사용자의 직접 입력만 포함한다. BE가 AI에 보내는 내부 요청에 다음 선택 필드를 추가한다.

```json
{
  "message": "강릉으로 2박 3일 여행",
  "region": "강릉",
  "travel_days": 3,
  "preferences": ["바다"],
  "travel_profile": {
    "traveler_type": "NATURE_HEALING",
    "tags": ["자연", "힐링", "산책"],
    "confidence": 0.82,
    "analysis_version": "travel-profile-llm-v1"
  }
}
```

AI는 프로필 태그를 낮은 가중치의 soft preference로 병합한다. 직접 입력과 충돌하면 직접 입력을 유지한다.

## 인증

- BE의 프로필 분석 및 코스추천 Client가 동일한 `X-Internal-API-Key`를 전송한다.
- AI의 `/internal/travel/profile/analyze`, `/internal/travel/plan` 모두 동일한 키를 검증한다.
- 운영 환경에서는 내부 키가 없으면 인증을 우회하지 않도록 배포 설정에서 필수로 지정한다.
- 키와 사용자 활동 원문은 로그에 기록하지 않는다.

## 구현 체크리스트

### AI

- [x] LLM-first 전체 프로필 분석과 구조화 출력
- [ ] 입력 활동 ID가 연결된 구조화 근거
- [x] 근거 존재·민감정보·Enum 검증
- [x] 검증 실패 시 결정론적 fallback
- [x] 여행 추천 요청에 선택적 `travel_profile` 추가
- [x] 직접 입력 우선 soft preference 병합
- [x] 두 내부 API 인증 통일
- [x] 단위·계약·회귀 테스트

### BE

- [x] 분석 활동 수집과 AI 호출
- [x] 사용자별 결과 upsert
- [x] 분석 Job 생성·Polling·완료 Job 정리
- [x] 프로필 유효성·버전 정책
- [x] 공개 추천 DTO와 AI 내부 DTO 분리
- [x] 인증 사용자의 유효 프로필을 추천 요청에 주입
- [x] 동기·비동기 추천 경로 일관성
- [x] 코스추천 Client 내부 인증 헤더
- [ ] 저장·만료·장애 유지·추천 주입 테스트
